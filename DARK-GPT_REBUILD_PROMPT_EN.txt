# MASTER PROMPT: REBUILD DARK-GPT

You are an expert software engineer and product designer. Rebuild a local AI assistant application called DARK-GPT based on the complete specification below. Treat this document as the source of truth. Produce a clean, maintainable, portable implementation. Do not replace the requested features with a generic chatbot demo.

## 1. Product Identity

Application name: DARK-GPT
Creator name: M4TH4CK3R
Subtitle: POWERED BY OLLAMA FREE
Purpose: a local, terminal-first AI assistant for lawful personal use, learning, software development, and authorized cybersecurity research.

The creator identity must appear under the large DARK-GPT title in a smaller, readable font. If the user asks who created the application, the application must answer automatically and deterministically:

"DARK-GPT a été créé par M4TH4CK3R."

This automatic creator answer must not require an Ollama request.

## 2. Technology Requirements

- Use Python 3.9 or newer.
- Use Ollama as the default local AI backend.
- Default model: llama3.2.
- Default API endpoint: http://127.0.0.1:11434/api/chat.
- Use the Ollama chat API with structured JSON messages.
- Keep the model loaded between requests with keep_alive when supported.
- Use a bounded generation length so the assistant does not generate unnecessarily long answers.
- Keep backend calls isolated in a clear provider function so additional providers can be added later without rewriting the user interface.
- Use requests or another small, well-maintained HTTP client.
- Do not require administrator privileges for local installation.
- Store user-generated data in a user-writable application directory.
- Never hardcode the original developer's absolute filesystem paths.
- Resolve paths relative to the application/project directory or the current user's home directory.

## 3. Terminal User Interface

Build a polished terminal UI. It must be readable, deliberate, and cyber-themed without looking like a debugging console or a stream of system errors.

Base palette for the chat: BLACK, WHITE, and RED only.

- Background: the user's normal black terminal background.
- User input and neutral instructions: white.
- DARK-GPT responses: vivid red.
- Main frames and important chat markers: vivid red.
- Avoid purple, cyan, green, and blue in the chat interface.
- Red is the primary branding color for the home menu and chat.
- Use ANSI colors safely and always reset the color after every colored segment.
- The interface must remain readable if ANSI colors are unavailable.

The animation should be dramatic but not excessively slow. Keep it usable on every launch.

## 7. Chat Experience

The chat must use the following visual convention:

- User prompt: white, for example `YOU >`.
- DARK-GPT response label: vivid red, with a small `[x_x]` marker.
- DARK-GPT response text: vivid red.
- Neutral instructions: white.
- Spinner while a real Ollama request is running: red.
- Chat header and borders: red.
- No purple, cyan, green, or blue in the chat.

The chat must preserve the full conversation context for the active session.

## 8. Response Behavior

Do not hardcode every conversational answer. Real questions must be sent to Ollama.

For short conversational questions such as:

- "T'as compris ?"
- "Tu as compris ?"
- "Ça va ?"
- "Bonjour"
- "Merci"

send the request to Ollama with a concise-response instruction and a small generation limit. The model must still analyze the conversation context before responding. Do not immediately return a hardcoded OK before contacting the model.

If Ollama returns only `OK`, `OK.`, or `okay` for a short confirmation question, replace that uninformative display result with:

"Oui, j'ai compris."

This replacement is only a presentation fallback after the real model request completed. It must not bypass the request or pretend that a model analysis happened when it did not.

Normal questions should receive normal model responses. Keep answers clear, useful, and reasonably concise.

## 9. Ollama Lifecycle

On macOS, support a user-local Ollama installation such as:

~/Applications/Ollama.app/Contents/MacOS/ollama

Detect Ollama in PATH and in common user-local application locations.

If the local API is unavailable on macOS, open Ollama.app in the background without taking focus, using the equivalent of:

open -gj Ollama.app

Wait for http://127.0.0.1:11434/api/tags to respond before sending chat requests. Show a clear, user-friendly message if the server cannot start.

Do not require a visible Ollama window or a second manual Ollama tab for normal use.

## 10. Memory and Sessions

Implement local, file-based session memory for the current desktop version.

Each session should contain:

- session ID;
- title;
- created timestamp;
- updated timestamp;
- messages with roles and content.

Support:

- create a session;
- open a session;
- list sessions;
- rename a session;
- search messages across sessions;
- export a session to readable text or JSON;
- delete a non-default session;
- preserve the active session after restarting the application.

Do not claim that the model has been retrained. Explain internally that this is contextual memory, not weight training.

For a future web version, the architecture should make it possible to add per-user persistent memory, preference extraction, semantic search, profiles, synchronization, and user-controlled deletion.
